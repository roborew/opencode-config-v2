# 0009 — Spike results: OpenCode 2.3.0 mechanisms

Status: accepted (2026-11-14)

Environment: OpenCode **2.3.0** installed isolated (`…/.spike-workspace/home/.opencode/bin/opencode`, untouched by the homebrew 1.19.0 and the live v1 config at `~/.config/opencode`). The test project used project-level config (`.opencode/`), which merges and overrides the same way the global config does. Model auth was unavailable (stale credential → 401), so model responses never completed — but every mechanism below is evidenced at prompt-admission or model-dispatch time, which run **before** any model call, captured from `opencode serve --print-logs` output.

Evidence labels refer to log lines produced by the throwaway spike plugin (`[SPIKE] …`) in runs on 2026-11-14. The throwaway project was deleted; only this ADR and the doc amendments were committed.

## Additional findings

- **Anti-cascade rule.** A plugin that creates worktrees unconditionally (e.g. from a timer in `setup`) recurses: every new worktree location loads the plugin again and creates another worktree (one test spawned ten). `oc-worktree` creates worktrees **only from tool calls**, guarded to the canonical checkout (`ctx.location.directory === ctx.location.project.canonical`).
- **@mention timing.** Mention parsing happens after prompt admission (`prompt.skills` was `null` in the hook even for a template containing `@spike-a`); hook-added skills resolve on the normal path and always loaded.
- **Skill precedence note for the Mac.** Robin's live `~/.agents/skills` (compat source) and old v1 config agents/skills loaded alongside the spike config. Once ticket 02's repo replaces `~/.config/opencode`, the global config source (higher precedence) wins for duplicated IDs, and the old config's agents disappear with it.
- **Model IDs verified** against the Go docs (2026-11-14): `deepseek-v4.1-flash`, `glm-5.3`, `minimax-m3`, `qwen3.8-max`, `kimi-k2.7-code`, `gpt-6-luna` all exist on `opencode-go` at the prices in blueprint §3. DeepSeek still requires the Global region in Go privacy settings. Free Go models exist (`beam-free`, `longcat-2.5-free`) if a zero-cost smoke model is ever needed.
- **CLI surface**: `opencode run` (with `--server`, `--agent`, `-m`), `serve`, `api` (server requires auth for external clients — a spawned server shares auth with CLI clients), `debug agents|config|paths`, `models`, `plugin`, `session`, `service`. `--print-logs` streams server logs; plugin `console.log` lines appear there.
